# 天空之城 · 无尽风之庭园

打开 `Boids_Proj/Assets/Boids/Scenes/SkyCityInfinite.unity` 并进入 Play。这是一张沿相机旅行持续生成的天空群岛地图。原来的精修固定城市仍在 `SkyCity.unity`。

## 128 个建模模块

16 个建筑家族，每家族 8 个结构变体。模块有不同的拱数、圆形或方形塔身、阶梯、分层塔楼、尖顶或穹顶、架空长廊、亭台和种植配置；旋转、镜像和换色不计入 128 个数量。`module-catalog.json` 保存每个模块的名称、连接掩码、三档三角形数量和几何 SHA-256。128 个最高细节模型具有 128 个不同的几何哈希。

家族包括：拱廊步道、转角游廊、市场柱廊、喷泉广场、悬空观景亭、穹顶圣所、钟楼、庭园回廊、梯田果园、宫廷图书馆、高架水道、转角天桥、仪式门楼、天文台、温室和冠冕宫殿。

- 可编辑 Blender 文件：`SkyCity_Modules.blend`。
- Unity 模块：`Assets/Boids/Art/SkyCityInfinite/Modules/` 中的 **128 个 Prefab**；每个含 LOD0 / LOD1 / LOD2 和连接标记。选中模块可看四向连接点。
- [模块总览](../../../Boids_Proj/Captures/SkyCityInfinite_128Modules.png)：每列一个家族，每行一个变体，来自实际 Unity 网格渲染。
- 运行时使用 `Assets/Boids/Resources/SkyCityInfinite/Modules.bytes` 的压缩共享模型词汇，按需组合区块；不会实例化所有 Prefab。

## 构图与变化

建筑依附于连续悬崖和台地，不再每栋楼带一个重复的锥形小岛。模块之外另有八种城市构图：风之宫殿、狭长修道院、双岩体空中花园、阶台书库、孤峰天文塔、开放水庭、桥上村落、残缺柱廊遗迹。它们有不同的横纵比例、植被密度、建筑权重和海拔；相邻及对角相邻街区不会使用同一种地标。

宫殿和高塔是局部重音，低矮花园、水面和云谷形成留白。八种构图不计入 128 个模块数量。Blender 源文件同时保存模块目录和岛屿构图；`build_districts.py` 复用原天空之城的雕塑式建模函数，生成圆顶肋线、实体窗洞、拱廊、树冠、藤蔓与悬崖。LOD 降低采样和叶片数量，保留支撑柱，避免远景只剩悬空屋顶。

## 生成与加载

每个区块内有 8 × 8 个 12 米模块格，区块中心相隔 168 米；岛体按类型有不同横纵比例，建筑基面高度为 5–60 米。WFC 从最低 Shannon 熵的位置开始观察，按区域建筑权重坍塌，并传播四向连接、中心庭院和相邻高塔限制。连接桥在云谷中伸展，桥口的平面位置和高度由两侧共用的边界确定，因此加载顺序不影响接缝。同一种子和坐标会恢复相同布局。

求解最多重试 8 次。若所有尝试均矛盾，使用满足同一接口规则的确定性保底布局，并增加诊断计数；不会提交带矛盾的随机结果。当前规则测试包含多个种子、正负坐标和十亿级坐标，报告保留重试与保底次数。

运行时的边界：

- **最多 25 个驻留区块**，加载优先级略向视线前方偏移；外围保留迟滞，容量不足时先回收不再需要的最远区块。
- **最多 2 个后台任务**，执行 WFC 和网格拼装；另允许 1 个主线程待上传区块。任务完成前不访问 `Task.Result`。快速转移会取消过时任务、废弃过时结果。
- **主线程调度预算默认 2 ms / 帧**，将区块分为四个建筑网格、一个水面网格和一个透明瀑布网格上传。预算在操作之间检查；单次上传不是可抢占操作，因此预算不等于绝对无尖峰保证。
- 每个区块只上传当前距离需要的一档 LOD；采用迟滞切换，避免临界距离来回重建。相机之外的网格由 Unity 视锥剔除，远景不投影。
- 建筑按区块补丁合并，共享材质；48 只随行燕子采用 GPU 实例绘制。没有逐栋 `Update` 或逐栋物理碰撞体。
- 最多复用 2 个空区块容器；卸载时释放其 Mesh，池中不积累旧地形。不会保存走过的所有区块或任务历史。
- 浮动原点在相机离局部原点约 384 米时平移。生成仍使用 `long` 街区坐标，云场保留周期坐标偏移。
- 云海使用半分辨率体积积分、96 个视线步进与 4 个光线采样；漂移的高云团分隔远景。最近的城市水庭使用一个 512 像素、最多 30 Hz 的实时平面反射相机；其他海拔暂用天空反射，靠近后切换至实时倒影，不复用错误高度的建筑倒影。

## 建筑合理性修复（2026-09-25）

桥上拱廊与桥下承重结构分开建模。柱脚落在桥面，柱头、拱券、檐梁、铜屋顶连续承接；长桥重复约 10–12 米的标准廊段，不再把短柱廊拉伸到整段云谷。桥下的连续拱肋和实心拱腹接入两端岛体，桥台向岩体内延伸。大高差连接增加实体踏步，桥缝共享横截面，斜桥使用正确的法线变换。

圆形拱廊统一以完成面高度定位上层楼板，柱头停在起拱线；宫殿各层、钟楼钟室和圆顶据此衔接。天文塔外挑回廊补入锥形承托；伸出台基的住宅、门廊补入落地基础；台阶有实体基础和平台出口。外围拱券嵌入挡墙，种植根部与台面齐平。修复尖屋顶退化四边形被丢弃的问题，三档细节都保留尖顶。

桥的两端都加载后才同步显现；卸载任一端时，同一帧隐藏连接桥，避免加载边缘出现指向空中的半座桥。可见性编码保存在桥网格中，继续使用原有四个建筑批次，不增加逐桥 GameObject、绘制批次或上传次数。

- `SkyCityInfinite_StructureValidation.json`：48 个桥梁 LOD、6 个尖顶 LOD、8 种岛形的 388 条连接、4,656 个桥面/廊顶接缝采样点，另检查 96 个拼装 LOD 的三角形法线与可见性标记。
- `SkyCityInfinite_StructureRuntime.json`：实际驻留集合与渲染属性核对，包括可见桥、隐藏桥和缺少对岸的异常桥计数。
- 八种地标的更新实拍见 [Gallery.md](Gallery.md)。这些检查验证视觉构造和网格连接；场景仍使用飞行游览相机，没有新增步行碰撞或室内路线。

## 水体修复（2026-09-25）

瀑布原先误合并进不透明建筑网格，导致透明、折射和末端消散全部丢失。模型库现在使用版本 3，明确分离建筑、水池和瀑布三种数据；每个区块多上传一个共享材质的瀑布批次，驻留上限仍为 25。

水庭经石砌水渠流向岛缘，下落曲面采用重力轨迹，流纹沿轨迹加速，宽度逐渐收束。独立透明材质提供背景折射、柔边、碎水和末端渐隐；少量 GPU 水雾随区块一起加载、卸载，无逐粒子 CPU 更新。生成建筑和种植为溢流口留出空间。池面保留实时倒影，并用随模块旋转的局部水流方向替代原固定场景的世界坐标出口。

- [实际运行近景](../../../Boids_Proj/Captures/SkyCityInfinite_Water.png)
- [5 秒实际水流录像](../../../Boids_Proj/Captures/SkyCityInfinite_Water.mp4)
- `SkyCityInfinite_WaterValidation.json` 记录录像帧数和实时反射更新次数；录像采用固定模拟步长，不作为性能测量。
- 资产验证覆盖八种岛屿的三档细节，检查瀑布未混入建筑、流动 UV、水雾与透明材质。Blender 文件内也分别保留水面与瀑布对象。

场景文件只含相机、太阳、后处理、音乐和流式管理等启动对象，**不预存整片城市**。共享模型词汇常驻内存，地图网格有固定上限。“无限”表示没有预建地图边界，受整数坐标范围与设备资源限制。

## 重建

1. 在仓库根目录运行：

   ```powershell
   & '你的 Blender 路径/blender.exe' --background --factory-startup --python ArtSource/SkyCity/Infinite/build_modules.py
   ```

2. Unity 等待导入编译后，选择 `Boids > Sky City Infinite > Build streaming world`。
3. 选择 `Bake 128 reusable prefabs`，更新可编辑模块；反复执行保留已有资产 GUID。
4. `Validate WFC constraints` 检查确定性、生成顺序、邻接、边界和取消。
5. `Render module atlas` 输出实际模块总览。
6. `Validate architectural connections` 检查桥面/屋顶接缝、桥台落点、法线、三档细节和尖顶导出。

Blender 脚本是当前运行时模型的权威制作源。仅手动改某个预览 Prefab 不会自动改写压缩模型库；应同步制作脚本并重新导出，以免作者预览与运行时不一致。

## 验证证据与测量边界

- `Captures/SkyCityInfinite_SolverValidation.json`：WFC 规则、重复生成和跨区块一致性。
- `Captures/SkyCityInfinite_AssetValidation.json`：128 个独立模块、384 个 LOD 网格、制作预览与运行时模型一致、八种城市构图和零预载区块。
- `Captures/SkyCityInfinite_PlayerPerformance.json`：独立 Windows 程序预热后连续旅行、快速远距离传送，再回原点的实际帧间隔；功能和性能分别判定。
- `Captures/SkyCityInfinite_Build.json`：独立程序构建结果。

性能报告同时保存设备、分辨率、P95 / P99 / 最大帧间隔、主线程流式开销、上传峰值、驻留上限、卸载数量和内存。测量区间不写截图或文件；首次资源加载、首次着色器预热和屏幕录制不混入稳态指标。图形驱动与操作系统内存不包含在 `ownedMeshPeakMiB` 中，完整 Unity 分配另列。目标帧率上限为 60；不能把这种有上限的测量当作无限制峰值 FPS，也不能推广到未测设备。

2026-09-25 水体修复后的前台独立程序实测：RTX 3090，1536 × 1024，65.01 秒、3893 个实际渲染帧；P95 帧间隔 16.67 ms，最大 33.02 ms。完成 235 个区块、卸载 210 个，驻留峰值 25、待处理峰值 3，零错误和零保底布局。流式主线程 P95 为 1.64 ms，单次网格上传峰值 1.94 ms。首座岛屿出现用时约 3.52 秒；共享模型库约 162.97 MiB，区块网格峰值约 148.10 MiB。首次加载与稳态游览分开报告。性能检查现在也要求最大帧间隔不超过 250 ms，并记录超过 100 ms 的异常帧。

前两轮复测出现约 2 秒的偶发长帧，其中一轮窗口尺寸也偏离设定；固定前台窗口后未复现。原因尚未完全定位，不能将前台通过推广为所有窗口状态都无停顿。两轮原始报告保留在 `Captures/SkyCityInfinite_WaterEarlierRuns.json`。

建筑修复后的最新独立程序复测：同一 RTX 3090、1536 × 1024，65.01 秒、3899 个渲染帧；P95 16.675 ms、P99 16.869 ms、最长 31.111 ms。完成 223 个区块、卸载 198 个，驻留峰值 25、待处理峰值 3、零错误/保底；区块网格峰值 163.08 MiB，共享模型库 161.13 MiB。流式 CPU P95 2.05 ms，最长 4.40 ms，单次上传峰值 2.73 ms；首次岛屿约 3.81 秒。桥梁拼装按最终顶点/索引数预分配缓存，减少列表扩容。

本次首轮仍出现 1.63 秒长帧，功能通过、性能未通过，原报告保存在 `Captures/SkyCityInfinite_StructureEarlierRuns.json`。预分配优化后的第二轮通过，但不足以证明首轮长帧全部由分配引起；保留前述窗口状态和系统调度的测量边界。

当前相机是游览相机，最低高度约 40 米；场景不是可步行进入室内的关卡。八种城市构图和 128 个模块是有限的美术词汇，长期旅行仍可能识别出同一套建筑语言；生成保证连接和局部构图变化，不代表每座城市都是独立手工创作。

算法与 API 依据：[原始 WFC 的观察—传播流程](https://github.com/mxgmn/WaveFunctionCollapse)、[Unity 2022.3 异步资源加载](https://docs.unity3d.com/2022.3/Documentation/ScriptReference/Resources.LoadAsync.html)、[实例网格绘制及批次限制](https://docs.unity3d.com/2022.3/Documentation/ScriptReference/Graphics.DrawMeshInstanced.html)。实现代码为本项目自行编写。
