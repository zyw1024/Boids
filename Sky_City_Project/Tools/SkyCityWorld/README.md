# 天空之城：第一人称世界

打开 `Assets/Boids/Scenes/SkyCityWorld.unity` 并进入 Play。编辑器中先点击 Game 画面。

| 操作 | 效果 |
| --- | --- |
| WASD + 鼠标 | 沿视线飞行、转向 |
| 滚轮 | 调整相机移动速度，2–36 m/s |
| Q / E、Shift | 下降 / 上升、加速 |
| 鼠标右键 | 在前方呼唤鸟群，盘旋后自然散开 |
| G | 瞄准主岛花坛播种，最远 45 m，墙体会遮挡 |
| Esc | 打开 / 关闭场景设置（鸟群 / 世界生成 / 空中花园） |
| F、M | 返回主岛、切换音乐 |

菜单打开时鼠标释放，相机停止响应操作，鸟群、云、水、旗帜和音乐继续运行。关闭菜单保留本次运行中的设置，不写入全局 PlayerPrefs。鸟群参数即时生效；世界生成参数先编辑、再应用。

## 鸟群调节

10 个滑杆：鸟群数量（16–128）、飞行速度、转向灵活度、感知半径、个体间距、分离 / 对齐 / 聚合权重、召集盘旋半径及停留时间。停留时间在正在进行的召集中也生效，缩短到已过去的时间会结束召集。

飞鸟模型池最多 128 个；第一次超过原始 64 只时扩充，其后复用模型和状态数组。未启用的飞鸟不渲染、不模拟。各小群的中心与方向按实际成员数计算，不依赖固定 16 只。避障始终保留。极端权重用于观察算法，不保证每种组合都维持默认的美术构图。

中文 UI 字体为 [Google Fonts 的 Noto Sans SC](https://github.com/google/fonts/tree/main/ofl/notosanssc) 的静态子集，重命名为 Sky City UI，附 SIL OFL 授权。`subset_font.py` 可从原始可变字体重建，只保留菜单使用的字符和 ASCII；新增中文文案后需重新生成字体。

## 风之树与苏醒花园

主岛包含一棵风之树、上下两层露台与水池两侧共四个花园区域。植物位置取自原 Blender 主岛的花坛坐标，避开水池、道路和花坛之间的空隙。新增植物网格由 C# 编辑器工具生成，原主岛建筑继续使用 Blender 模型。无限街区也已接入同一套递归树木、花园演化、播种与设置系统。

**分形树**采用有限层级、带种子的参数化递归分枝：`F(l,r,d) → 弯曲枝段 + 多个 F(约 0.73l, 0.58r, d+1)`。粗枝与细枝共享分枝规则，长度和角度带确定性扰动；树冠受开阔侧的空间范围约束。3 / 4 / 5 层分别有 31 / 67 / 139 段枝干，各保存近、远两级网格。菜单切换已缓存的层级，不在运行时反复重建树。生长播放由材质依次伸展枝段，枝叶风动与花瓣舒展也在 GPU 处理。

**元胞自动机**使用四状态、Moore 八邻域、双缓冲同步更新：休眠格子达到盛开邻居阈值后萌芽，随后盛开、恢复、再进入休眠。每代读取上一代的全部状态，不依赖遍历顺序。四个表面共 558 格，其中 372 格可种植；其余格子是花坛间隙，不能被播种或传播。视觉表现为合并网格中的花草，格子不会成为独立 GameObject。

「空中花园」页可调整递归层数、风动、演化速度、萌芽所需邻居数、盛开和恢复时长；可以播放树木生长、唤醒花园、清空花潮、开关规则视图。规则视图的蓝 / 绿 / 金 / 紫分别对应真实的休眠 / 萌芽 / 盛开 / 恢复状态。

默认开启稀疏的风播种：每个附近花园约每 3.8 个模拟秒收到一粒确定性种子；之后的传播仍由元胞规则完成。它是可关闭的外部输入，避免所有花朵恢复后永久静止，不能把它误讲为邻域规则自发创造种子。「清空花潮」同时关闭风播种，方便从单颗种子开始授课。G 播种成功后，一小群鸟会短暂靠近该区域；右键召集仍具有优先权。

模拟仅在相机距离花园 100 m 内运行，默认每秒 5 代，演化速度滑杆范围为 0.25–3 倍。状态纹理在代与代之间平滑过渡，不随每个渲染帧重建网格。远处停止模拟；主岛已有的 480 m 可见性关闭继续生效。主岛状态保留在内存中，浮动原点随主岛一起移动。

### 无限街区中的植物

`SkyCityDistrictBotanyLayout` 明确记录 Blender 模块的种植位置：拱廊外侧空地、符合变体条件的花园回廊、梯田果园的既有台面。位置采用和建筑相同的模块旋转、岛体横纵缩放与海拔。街区最多四个花坛、两棵递归树；无合适种植模块的位置保持原建筑。每个花坛有 12 × 4 个连续元胞，使用共享花草网格和独立状态纹理。

`SkyCityDistrictGardens` 监听完成上传和即将卸载的街区，在每帧最多一个街区的预算下接入植物。花园网格和三个树木层级由编辑器预生成，所有街区复用；花园状态和材质参数独立。植被在街区中心约 260 m 内显示，100 m 内才演化。加载范围设为一、二、三圈时，街区及植物的内存数量一起受 9 / 25 / 49 的上限约束。

卸载时把元胞相位、年龄、代数与风播种序列写入本次运行专属的临时目录，释放场景对象及状态纹理。返回时按整数街区坐标、种子和布局指纹恢复。这样探索距离不会累积常驻植物对象；临时文件数量随访问范围增加，退出世界时删除，不跨次运行保存进度。切换 WFC 种子或布局使用独立状态键，避免把旧花园错放到新建筑上。控制菜单的「唤醒花园」作用于附近花园，「清空花潮」清空当前已加载的花园并关闭风播种。

主岛卸载后，全局街区控制器继续转发 G 播种及生长动画，Esc 菜单仍能控制所有已加载花园。右键呼唤鸟群的优先级继续保留。

新增街区验收：35 个布局的四项种植检查通过；更名后的工程构建成功，错误与警告均为 0。独立程序 `-district-garden-review -garden-output "绝对路径.json"` 的 20 项功能检查全部通过，包括离开主岛后播种、菜单隔离、树层级和规则视图、元胞传播、卸载后精确恢复及继续演化、换种子、加载范围 9 → 49 → 25、共享网格与总量限制。该验证始终明确调用 URP HDR 离屏渲染。最终 RTX 3090 / 1600×900 复测实际渲染 1,254 帧，P95 22.968 ms、P99 37.165 ms，最大 70.880 ms，错误 0；最大尖峰发生在远端花园阶段。完整分段数据见 `Captures/SkyCityWorld/DistrictGardens_Runtime.json`。性能数字取自最终构建的这一次采样，不代表始终稳定 60 fps。下文原有 22 项花园检查记录的是主岛样板，保留作为历史回归依据。

`SkyCityGardenBuilder.Build()` 重建样板及缓存网格；`SkyCityGardenReview.Run()` 检查同步性、确定性、土壤边界、阈值行为和树网格。独立程序使用 `-garden-review -garden-output "绝对路径.json"`，验证真实 UI 回调、瞄准播种、菜单输入隔离、鸟群召集、生长动画、百万街区坐标往返与实际渲染耗时。它调用公开输入处理函数，不冒充物理键盘测试。

后台隐藏窗口时，额外加 `-garden-offscreen`：明确调用完整 URP 相机渲染至 1600×900 HDR RenderTexture，水面反射仍参与。隐藏窗口默认会跳过显示渲染，不能把空跑 Update 的帧率作为画面性能。屏幕叠加菜单在编辑器单独做视觉检查。

花园验证记录：10 项算法 / 网格检查通过；独立程序 22 项功能检查通过。RTX 3090，1600×900 离屏复测实际渲染 1,684 帧 / 28.093 秒，P95 16.668 ms、P99 16.843 ms，最大 31.824 ms，运行错误 0，驻留街区峰值 25、待处理任务峰值 3。近景、远处加载、返回加载和稳定花园分别记录在 `BotanyRuntime.json`。此前首轮同类离屏测试 P95 35.869 ms、P99 62.586 ms、最大 94.970 ms，提示初始化或环境负载可能造成尖峰，原因尚未隔离；复测不能代表所有首次启动或硬件都能稳定 60 fps。

2026-09-26 续接验收：刷新脚本并等待编译完成后重新构建，构建错误和警告均为 0；最终构建的 22 项功能检查全部通过。相同 RTX 3090 / 1600×900 离屏条件下，实际渲染 1,685 帧 / 28.090 秒，P95 16.668 ms、P99 16.748 ms，最大 17.255 ms，运行错误 0。结果保存在 `Captures/SkyCityWorld/BotanyRuntime_Release.json`；前次结果保留在 `BotanyRuntime.json`。这段采样从街区初始化完成后开始，不覆盖冷启动时间。构建期间 Unity 自动改写的 URP 预筛选缓存和 Burst 设置版本字段已恢复，场景配置无额外调整。

## 世界生成设置

在 Esc 菜单选择「世界生成 · WFC」。

| 参数 | 对生成的影响 |
| --- | --- |
| 随机种子 / 换个种子 | 相同种子和参数可确定性重建；输入必须是有效的 32 位整数 |
| 桥梁连接概率（0–100%） | 改变共用边界上的桥梁出现概率，两侧使用同一边界键；原点的固定入口例外保持兼容，主岛保留区域不生成连接到空单元的桥段 |
| 岛缘完整度（35–100%） | 改变可选岛缘地块的保留概率；主路径、入口和中心地块仍保留，固定裁角也保留 |
| 花园模块权重（0.2–4 倍） | 增减花园回廊、梯田果园及温室模块的选择倾向 |
| 高塔模块权重（0.2–4 倍） | 增减钟楼、天文台、冠顶宫殿模块的选择倾向，仍受位置和相邻高塔约束限制 |
| 区域风格统一度（1–4 倍） | 增大同一组区域优选外观变体的相对权重；1 倍为无偏好 |
| 求解尝试上限（1–8 次） | 包含第一次求解，最多在矛盾后重试上限减一次；耗尽时使用保持连接约束的兜底布局 |
| 加载半径（1–3 圈） | 即时调整候选范围和驻留上限：9 / 25 / 49 个街区；主岛占用的单元不再重复生成 |
| 每帧生成预算（0.5–4 ms） | 即时调整主线程上传与卸载的时间预算；单次原子网格操作仍可能略超预算 |

点击「应用并更新街区」才提交种子、概率和权重。旧街区保持显示，后台生成新布局后逐块上传并替换。每份任务持有不可变参数快照和版本号；连续应用取消旧任务，晚到的旧结果无法覆盖新版本。更新期间只有两个端点属于同一版本的桥才显示，避免两套边界拼接。相机位置、主岛模型、鸟群设置保持不变。

「恢复默认参数」将生成参数恢复为进入场景时的草稿，仍需点击应用；加载范围及预算立即恢复。扩大范围增加网格内存与绘制开销，缩小范围按帧预算逐批卸载，不在一帧内清空世界。

## 世界与性能边界

- 保留空中花园的精细模型、烘焙间接光与材质，作为中央到达区；周围使用既有 WFC 模块生成可探索的浮岛城区。没有把低成本背景剪影作为真实城区。
- 主岛区域占用原点单元，流式生成跳过此单元和通向被省略单元的桥段。默认最多保留 25 个城区，可设为 9 / 25 / 49；同时最多 2 个生成任务及 1 个上传阶段，远处卸载；近处才启用网格碰撞。
- `Physics.BakeMesh` 在工作任务中处理每个独立网格；完成后交换碰撞网格。卸载等待相关任务结束，避免读取已销毁网格。
- 第一人称相机使用 CharacterController。浮动原点与传送时暂时禁用碰撞体再移动，防止物理缓存把相机拉回旧坐标；主岛位置由原点坐标重新计算，避免大坐标往返损失精度。
- 主岛云密度 / 遮光缓存跨 280 m 单元重叠混合，维持连续体积云海。单份 32 MiB 缓存复用；反射使用同一云海与实时水面。
- 新场景独立于原固定构图样板，沿用 Unity 2022.3.62f2c1 / URP 14。周边模块与精细主岛仍存在美术质量差异，需要后续逐类重制。

## 重建、调试与实况

`SkyCityWorldBuilder.Build()` 从主岛样板创建世界；`BuildPlayer()` 构建 Windows 独立程序。修改现有场景通常不需要重新 Build 场景。

以 `-skyworld-review -skyworld-output "绝对路径.json"` 启动独立程序，可运行约一分钟的实际渲染验证，覆盖输入处理、碰撞、鸟群聚集 / 散开、跨区流式加载、浮动原点、百万坐标往返及确定性。性能测量时不截图；结果位于 `Captures/SkyCityWorld/Review.json`。公开输入处理函数测试与真实按键测试分开报告。

Unity MCP 可读写实际 Slider、回读群体参数、切换菜单、检查 Console，并用 `ScreenCapture.CaptureScreenshot` 截取包括菜单的 Game 画面，无需接管桌面鼠标。相机 RenderTexture 截图不包含 Screen Space Overlay 菜单。

`SkyCityWfcSettingsReview.Run()` 在后台检查默认求解器、极端参数的局部连接与街区边界、确定性及权重对结果的实际影响。独立程序使用 `-wfc-settings-review -wfc-settings-output "绝对路径.json"` 检查菜单草稿、无效种子、连续应用、旧任务隔离、加载上限 49 → 9 → 25、默认布局恢复及实际渲染性能。相关结果分别保存为 `WfcSolver.json`、`WfcRuntime.json`。

Play 模式执行 `SkyCityWorldReview.Record()`，用 Unity Recorder 录制 30 秒 1920×1080 / 30 fps 的实际场景游览与菜单演示，包含音频。输出临时目录 `SkyCityWorld/FirstPersonJourney.mp4`。游览使用脚本相机路径，不冒充人工游玩，也不作为性能基准。

`SkyCityLivingWorldRecorder.Record()` 录制 72 秒的最新游览，包含主岛鸟群召集、递归树生长、元胞花潮、真实菜单和远端街区花园；输出临时目录 `SkyCityWorld/LivingCityJourney.mp4`，同时保存章节说明及实际相机截图。它使用 Unity Recorder 和脚本相机路径，也不作为性能基准。

## 验证记录（2026-09-26）

Windows 独立程序，RTX 3090，1600×900，60 fps 上限，默认 64 只鸟：52.017 秒实际渲染 3120 帧，P95 16.671 ms、P99 16.786 ms，最大 17.582 ms；GPU P95 12.333 ms。鸟群与召集点平均距离从 37.93 m 降到 5.97 m。加载 128 个 / 卸载 104 个城区，峰值驻留 25 个、待处理 3 个任务，3 次浮动原点移动；百万坐标往返及主岛位置恢复通过，运行错误 0。构建错误与警告均为 0。

菜单另经 Unity MCP 检查全部 10 个滑杆的上下限、活动飞鸟实际数量（16 / 128）、模型池复用、默认值恢复、指针释放 / 锁定与相机姿态保持。真实 Esc 开关、拖动数量滑杆、恢复默认、菜单内 W / 右键输入隔离也完成检查。上述性能数据对应默认 64 只鸟，不代表所有极端参数组合。

WFC 设置增加后，默认求解器的 108 个街区回归通过，新增 118 次带参数求解通过；共检查 18,144 对局部连接与 1,728 对跨街区接口，均无矛盾。32 个权重对比样本全部产生不同布局，花园 / 高塔 / 优选变体的出现次数符合权重方向。

独立程序设置热更新测试通过：参数草稿不提前生成、无效种子被拒绝、连续两次应用采用最后版本、驻留上限 49 → 9 → 25、默认布局指纹恢复、主岛与相机位置不变。短时切换采样实际渲染 63 帧 / 1.305 秒，最大帧耗时 33.686 ms，峰值 48 个程序街区、3 个待处理任务、运行错误 0；这是集中热更新的短时压力检查，不是长时间游览性能基准。
